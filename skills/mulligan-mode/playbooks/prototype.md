# Prototype

A throwaway experiment that exists to make one decision cheaply. Speed matters more than polish; the rigour is in choosing well.

1. **Name the decision.** Which layout, which interaction, which approach performs better? No decision, no prototype.
2. **Build it outside production code** — a scratch directory or a sandbox branch — with the lightest tools that show the idea. No framework, tests or abstractions.
3. **Build the alternatives side by side** so they can be compared directly (Try two real shapes). Propose a variation the developer did not ask for when it is worth seeing.
4. **Observe the thing being decided:** screenshots, timings, printed output.
5. **Recommend,** with the trade-offs. The real build follows the **Feature** playbook.

**Reply:** the variants, the evidence, your recommendation, and where the throwaway code lives. Say plainly that it is throwaway.
